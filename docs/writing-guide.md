# 執筆ガイド（概要）

CHANGELOG の内容を「結論先出し・短文」のダイジェストへ再構成するときの考え方の要点。
図の具体的な SVG スニペット・プレースホルダ一覧・文字数上限などの詳細規約は
[templates/DIAGRAM_GUIDE.md](../templates/DIAGRAM_GUIDE.md) を参照（ここでは重複させない）。

## 基本方針

- **手本は X の AI インフルエンサー投稿の文体・構成**（投稿文そのものを載せるセクションは無い）。
- CHANGELOG の文をそのまま貼らない。主語をユーザーにして「何が嬉しいか」を自分の言葉で書く。
- 結論を先に。読み手が最初の 1 文で「何が起きたか」を把握できること。
- 1 文は短く。専門用語は最小限、使う場合は言い換えを添える。
- 破壊的変更の判定は保守的に（挙動が変わりユーザーの対応が必要なものだけ）。
- feed 以外の情報源で推測して書かない（CHANGELOG に無いことは書かない）。

## 成果物と役割分担

| ファイル | 役割 |
|---|---|
| `out/<version>/report.html` | 詳細版（図・4 列の機能一覧など） |
| `out/<version>/card.html` → `card.png` | まとめ画像（メール本文に埋め込む 1 枚絵） |
| `out/<version>/summary.md` | ヘッドライン＋3 行でわかる＋今日やること（プレーンテキスト代替） |

文字数上限・プレースホルダ名・SVG のテンプレートは `templates/DIAGRAM_GUIDE.md` に一本化されている。
執筆時は同ファイルを都度参照し、上限を超えたら文言を削って収める（フォントサイズを変えて逃げない）。
