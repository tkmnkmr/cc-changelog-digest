auto mode の判定方式が変更、MCP の長い処理は自動で裏へ

01 3行でわかる

  • 1テレメトリ等を切った環境の auto mode は、旧判定に戻らず確認か拒否になる
  • 2MCP の長いツール呼び出しが自動で裏に回り、待たずに作業を続けられる
  • 3Bash の権限すり抜けや worktree のサンドボックス脱出など、安全面の修正が多数

02 何が変わる・何が嬉しい

時間のかかる MCP ツールを使っても、会話が止まらず並行で進められる。

03 注目トピック

BREAKING

auto mode のフォールバック廃止

テレメトリや機能フラグを切った環境・LLM ゲートウェイ配下では、サーバーで判定できない操作は確認か拒否に。旧分類器を使うには CLAUDE_CODE_AUTO_MODE_SERVER=0。self-paced /loop も再予約せず終了する挙動に変更。

MAJOR

MCP タスクと確認待ちの自動拒否

MCP サーバーがタスクとして実行する処理を即バックグラウンドへ。permissions.denyInsteadOfPrompting で、確認待ちになる操作を拒否扱いにしてターンを止めない。

MODEL
該当なし

05 影響を受ける人・今日やること

  • LLM ゲートウェイ等で auto mode を使う人 → 確認が増えたら AUTO_MODE_SERVER=0 を検討
  • self-paced /loop を使う人 → 旧挙動が必要なら CLAUDE_CODE_LOOP_KEEPALIVE=1 を設定
  • MCP の結果を同期で待ちたい人 → CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND を設定
